# DealFlow360 Demo Flow Audit & Discovered Bugs

This document tracks functional bugs, UI/UX glitches, accessibility issues, and demo flow hiccups discovered during the end-to-end browser walkthrough.

---

## 1. Accessibility & Form Labels

- [x] **Missing accessible label / aria-label on Quotation Line Inputs**
  - **Location:** Quotation Editor (`/quotes/[id]`) - Line Items table (`Quantity` and `Discount %` inputs).
  - **Issue:** The `<input>` elements for line item quantity and discount percentage do not have `aria-label` or `<label for="...">` associations (`name: ""` in accessibility tree). Screen readers cannot clearly identify the input purpose.
  - **Expected:** Each input should have `aria-label="Quantity for [Product Name]"` and `aria-label="Discount percentage for [Product Name]"` or corresponding `id`/`htmlFor` labels.

- [x] **Missing accessible label / aria-label on Subscription Quantity input**
  - **Location:** Subscription Detail (`/subscriptions/[id]`) - Actions Card.
  - **Issue:** The `<Input placeholder="Qty" ... />` has no `aria-label` or `<label>` element.
  - **Expected:** Add `aria-label="New subscription quantity"`.

## 2. Quotation Editor & Validation

- [x] **Out-of-range discount input results in unhandled 500 `INTERNAL` error instead of client validation / 400 error**
  - **Location:** Quotation Editor (`/quotes/[id]`) -> Save changes / `saveQuote` action.
  - **Issue:** Entering a discount value > 100 (e.g. `118` or `1818`) is accepted by the React state in `<Input min={0} max={100} ... />` without inline error feedback or clamping. When saved, `src/features/quotes/engine/pricing.ts` throws `RangeError: Discount for line 1 must be a percentage from 0 to 100.`, which crashes the API route with HTTP 500 and renders `"INTERNAL: The request could not be completed"` on the UI.
  - **Expected:**
    1. Client-side: The input should clamp to `0-100` or display an inline validation warning before enabling Save.
    2. Server-side: Input out-of-range should return HTTP 400 `INVALID_ARGUMENT` with a friendly message (`Discount must be between 0% and 100%`) instead of an unhandled internal 500 error.

- [x] **Lines filtered / lost if `saveQuote` receives empty or mismatched `lines` payload**
  - **Location:** `src/server/live/commands.ts` (`saveQuote` handler).
  - **Issue:** `q.lines = q.lines.filter((l) => changes.some((c) => c.id === l.id));` silently deletes all existing quote lines if `changes` payload is empty or has non-matching line IDs. Dedicated line deletion should happen via `removeLine`, or `saveQuote` should guard against unintentional line wiping.
  - **Expected:** `saveQuote` should safely update existing lines without wiping all lines if `changes` is missing or out-of-sync.

- [x] **Dynamic `useId()` instability across error banner mounting causes DOM selector shifts**
  - **Location:** Quotation Editor (`Quotes.tsx`).
  - **Issue:** When error alerts mount or unmount, React 19's autogenerated IDs (`#_r_u_`, `#_r_v_`) shift indices, causing form input association or automation targeting mismatch.
  - **Expected:** Form inputs in the line items table should use stable keys / deterministic IDs based on `line.id`.

- [x] **Misleading copy: Sales Rep edits marked as "Customer proposed these changes"**
  - **Location:** Deal Flow Next Step Card (`DealFlow.tsx` lines 52, 60).
  - **Issue:** When a quotation is already shared (`q.sent === true`), any edit made by the sales rep sets `q.stage = "UNDER_NEGOTIATION"`. The card then claims `"[Customer Name] proposed these changes"`, even though the sales rep just made and saved the changes.
  - **Expected:** The next step card should check who made the last change (e.g., check `q.events[q.events.length - 1].actor` or `senderId`) rather than blanket-attributing all revisions during negotiation to the customer.

- [x] **Draft state desync on `submitQuote` renders false "Unsaved changes" immediately after submission**
  - **Location:** Quotation Editor (`Quotes.tsx` `useEffect` sync).
  - **Issue:** `submitQuote` does not increment `q.revision` or update `q.at`, but updates stage to `PENDING_APPROVAL`. The `useEffect` dependencies `[q.id, q.revision, q.at, q.evaluation.status, q.evaluation.step]` do not fire, leaving the local `draft` out-of-sync with `q` and immediately showing "Unsaved changes" (Save changes / Discard).
  - **Expected:** Include `q.stage` in the `useEffect` dependency array, or explicitly reset `setDraft(structuredClone(q))` upon successful action dispatch.

## 3. Fulfillment & Inventory

- [x] **Consolidate backorder crashes with Postgres Check Constraint violation (`Backorder_quantity_positive`)**
  - **Location:** `src/server/inventory/prisma-inventory.ts` (`saveBackorder`) and `src/server/inventory/service.ts` (`consolidate`).
  - **Issue:** When a backorder is fulfilled during consolidation, its `remainingQuantity` drops to `0`. `saveBackorder` attempts to persist `quantity: 0` into the `Backorder` table:
    ```typescript
    const quantity = backorder.status === "CANCELLED" ? 0 : backorder.remainingQuantity;
    ```
    PostgreSQL schema enforces `CHECK (quantity > 0)` (`Backorder_quantity_positive`). The database rejects the update with error code `23514` (Prisma code `P2039`), causing the HTTP request `/api/fulfillment/[orderId]/consolidate` to fail with 500 and display "Unexpected server error" in the UI modal.
  - **Expected:** In the Prisma schema, either the `Backorder` table should store initial quantity and `resolvedAt`, or if `quantity` represents remaining quantity, the constraint must permit `0` when `resolvedAt IS NOT NULL` / status is fulfilled, or `saveBackorder` should retain the original `quantity` (or delete the fulfilled backorder row).

## 4. Invoices & Billing & Subscriptions

- [x] **Missing currency formatting on Invoice Line Items list**
  - **Location:** `src/features/billing/ui/InvoiceDetail.tsx` line 158.
  - **Issue:** Line total amounts in the "Lines" section are rendered directly as `{line.lineTotal}` instead of using `<Money amount={line.lineTotal} currency={row.currency} />`. This causes raw unformatted strings like `41000.00` and `984.00` to display without the currency symbol (`₹`) or localized thousands separators.
  - **Expected:** Line totals should be wrapped in `<Money amount={line.lineTotal} currency={row.currency} />` matching the rest of the amounts card.

- [x] **Missing currency formatting on Subscription Unit Price and Proration Adjustments**
  - **Location:** `src/features/billing/ui/SubscriptionDetail.tsx` lines 56 and 106.
  - **Issue:** Unit price and change log adjustments are displayed as raw numeric strings `{sub.unitPrice}` (e.g. `1000.00`) and `{c.adjustmentAmount}` (e.g. `1933.33`) instead of formatted currency with currency symbol (`₹1,000.00`, `₹1,933.33`).
  - **Expected:** Render using formatted currency with currency symbol.

## 5. Deal Health & Risk Tasks

- [x] **Role RBAC mismatch: Finance Ops can access Deal Health and open Follow-Up dialog, but submitting throws 403 Forbidden**
  - **Location:** `/health` -> Create follow-up dialog -> `src/server/live/commands.ts` line 361.
  - **Issue:** In `src/server/live/commands.ts`:
    ```typescript
    if (action === "refreshHealth") {
      roles(actor, "ADMIN", "SALES_MANAGER", "SALES_REP", "FINANCE_OPS");
    ...
    if (action === "task") {
      roles(actor, "ADMIN", "SALES_MANAGER", "SALES_REP");
    ```
    Finance Ops (`FINANCE_OPS`) is granted access to the Deal Health view and can refresh health checks and click the "Create follow-up" action button. However, submitting the follow-up task throws `FORBIDDEN: Your role cannot perform this action`.
  - **Expected:** Either include `"FINANCE_OPS"` in `roles(actor, ...)` for `action === "task"`, or hide the "Create follow-up" action button for roles lacking task creation permissions.
